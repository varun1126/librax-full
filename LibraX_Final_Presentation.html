PROJECT OVERVIEW

Digital Modernization of Academic Library Operations
• Background of the Project Idea

Campus libraries handle thousands of volumes and active student patrons. Traditional paper-bound registers and legacy desktop software fail to deliver the speed, transparent reporting, and remote self-service students require.

• Real-World Problem Addressed

Long circulation desk queues, unrecorded book returns, opaque fine tracking leading to student disputes, and zero remote visibility into available shelf stock.

• Short Description of Proposed Solution

LibraX is a high-speed, web-native Library Management System engineered with a decoupled Java 21 Spring Boot REST backend and an intuitive React 18 + TypeScript frontend. Features real-time circulation tracking, Google Books API cataloging, and automated fine enforcement.

• Target Users & Application Area

Target Users: University Librarians, Department Staff, and Undergraduate/Postgraduate Students.
Application Area: College Resource Centers, Central Libraries, and Research Collections.

PROBLEM STATEMENT

Challenges in Conventional & Manual Library Systems
1. Operational Friction
  • Manual Accession: Manual data entry for ISBN, titles, and authors takes significant staff hours.
  • Desk Congestion: Physical queues at issue counters create severe peak-hour bottlenecks.
  • Lost Issue Slips: Missing physical slips lead to untracked asset loss.
2. Circulation Blindspots
  • No Real-Time Stock: Students cannot check whether books are available before traveling to the library.
  • No Hold Queue: Unavailable books cannot be fairly reserved when copies are checked out.
  • Untracked Renewals: Inability to monitor borrowing durations and limits.
3. Accountability Issues
  • Subjective Overdue Dues: Manual calculation of days late leads to arithmetic errors and student disputes.
  • Zero Cashier Auditing: Lack of digital receipts and cashier telemetry for collected penalties.
  • Data Desynchronization: Standalone spreadsheets lose state across computer reboots.

ALGORITHM / WORKFLOW

Circulation Checkout & Return State Machine
Step 1 & 2: Validate

1. Input Verification: Receive student_id and book_id via authenticated REST request.

2. Status Verification: Check student status is ACTIVE and active loans < 3 books limit.

Step 3: Stock Logic

Available Stock > 0: Decrement available_copies by 1; establish new loan with 14-day due date.

Available Stock == 0: Place request in holds table with next sequential queue_pos.

Step 4: Return & Fines

On Book Check-in: Increment available_copies by 1.

Overdue Formula: fine = max(0, days_late × Rs. 2.00). Log pending fine record in database.

Step 5: Output

Client Sync: Return 200 OK with updated loan DTO.

Real-time UI: Member borrowing badge updates instantly from 0/3 to 1/3 without page reload.

holds id, book_id, member_id, request_date, queue_pos, status FIFO reservation queue for checked-out books. Supports self-service student unhold.
fines id, loan_id, member_id, amount, paid_amount, status, payment_method Manages overdue penalty assessments (Rs. 2.00/day) and cashier settlement logs.
